# Meesho Seller Dashboard — DEMO (PHP + MySQL)

A complete, locally hosted **demo** seller dashboard built with **PHP, MySQL, HTML, CSS,
Bootstrap 5 and JavaScript (Chart.js)**. It shows orders, payments and reports the way a
marketplace seller panel would — using **generated sample data stored in your own MySQL
database**.

> ### ⚠️ DEMO MODE
> This project is **not affiliated with, endorsed by or connected to Meesho**.
> It does **not** call any Meesho API and contains **no real seller or customer data**.
> Every order, product, customer and payment row is invented sample data generated by
> `database/install.php`. Keep demo data separate from any real data.

## 🚀 Install on XAMPP (2 minutes)

1. Start **Apache** and **MySQL** in the XAMPP control panel.
2. Copy this folder to `C:\xampp\htdocs\mesho` (or `/Applications/XAMPP/xamppfiles/htdocs/mesho`).
3. **Either** open the installer and click one button:

   ```
   http://localhost/mesho/database/install.php
   ```

   **Or** import the SQL files in phpMyAdmin:
   `database/schema.sql` first, then `database/seed.sql`.

   **Or** from a terminal:
   ```bash
   php database/install.php            # install / refresh sample data
   php database/install.php --drop     # drop and rebuild everything
   ```

4. Open **`http://localhost/mesho/`** and log in.

## ☁️ Deploy to Railway (public URL)

> ⚠️ `something.railway.internal` is a **private network address**. It resolves only
> between services inside the same Railway project, so it will *never* open in a
> browser — that is expected, not a bug. You need a **public domain** instead.

1. **Generate a public domain**
   Service → **Settings** → **Networking** → **Public Networking** → **Generate Domain**.
   Railway gives you something like `xxxx-yyyy.up.railway.app` — that is the URL to open.

2. **Add a MySQL database**
   Project canvas → **+ New** → **MySQL**. A second service appears in the project.

3. **Point the PHP service at that database**
   Open the **MySQL** service → **Connect** tab → add these variables to the PHP
   service's **Variables** tab using Railway references:

   | Variable | Reference value |
   |----------|-----------------|
   | `DATABASE_URL` | `${{MySQL.MYSQL_URL}}` |

   `MYSQLHOST` / `MYSQLPORT` / `MYSQLUSER` / `MYSQLPASSWORD` / `MYSQLDATABASE`
   work too — `config/db.php` reads whichever you provide (URL first, then the
   individual variables, then `MS_DB_*`, then the local XAMPP defaults).

4. **Seed the demo data**
   After the deploy is *Active*, open
   `https://<your-public-domain>/database/install.php` and click **Install**.
   The very first install needs no login; once data exists, rebuilding it
   requires logging in first (so strangers can't wipe the demo).

5. Log in at `https://<your-public-domain>/` → `admin` / `admin123`.

No other configuration is required: the repo contains `composer.json`, so
Railway's builder detects PHP and installs the `pdo_mysql` + `mbstring`
extensions, and `index.php` at the repo root becomes the document root.

## 🗄️ Database

Database name: **`mesho_demo`** (default XAMPP credentials: user `root`, empty password —
change them in `config/db.php`, which is the single place where credentials are
resolved; `database/install.php` reads the same file).

| Table | Purpose |
|-------|---------|
| `users` | Login accounts (bcrypt `password_hash`) |
| `products` | Demo catalogue (42 products, 12 categories) |
| `orders` | 1,400 demo orders spanning the last 24 months |
| `payments` | **One row per order** (UNIQUE `order_id`) with its own payment status |
| `settings` | Store profile + dashboard preferences |

### How totals are calculated (and why nothing is double counted)

**1. Order status holds exactly ONE value per order**

```
Pending | Delivered | Returned | Cancelled
```

A returned order is *not* also counted as delivered, and a cancelled order is *not*
counted anywhere else:

```
Total Orders = Pending + Delivered + Returned + Cancelled
```

**2. Payment status is stored separately**, in the `payments` table:

```
Received | Pending | Refunded | Cancelled
```

**3. Money totals (all computed by SQL from database rows):**

| KPI | Formula |
|-----|---------|
| Total Payment | `SUM(order_amount)` where `order_status <> 'Cancelled'` |
| Received Payment | `SUM(payment.amount)` where `payment_status = 'Received'` |
| Pending Payment | `SUM(payment.amount)` where `payment_status = 'Pending'` |
| Refunded Payment | `SUM(payment.amount)` where `payment_status = 'Refunded'` |

Because `payments.order_id` is **UNIQUE**, the `orders → payments` join is strictly 1:1,
so no query can ever inflate a count or a total.

```
Total Payment = Received + Pending + Refunded
12,96,781     = 7,64,518 + 3,80,644 + 1,51,619   ✅
```

## 🔒 Security

- **PHP sessions** for authentication, `require_login()` guard on every protected page
- `session_regenerate_id()` on login, password change and periodically afterwards
- **Prepared statements everywhere** (`PDO::ATTR_EMULATE_PREPARES => false` — real server-side prepares)
- **CSRF tokens** on every POST form (`hash_equals` comparison → HTTP 419 on mismatch)
- **Whitelisted filters**: statuses/month/year/per-page validated against fixed lists before use
- **Output escaping** with `e()` (`htmlspecialchars`) on every echoed value
- `password_hash()` / `password_verify()` for passwords
- HttpOnly + SameSite session cookies; `database/.htaccess` blocks downloads of `.sql` files
- Login errors are generic (no username enumeration), all inputs length-limited

## 🛠️ Troubleshooting

| Problem | Fix |
|---------|-----|
| "Could not connect to the demo database" | Start **MySQL** in XAMPP, then open `database/install.php` |
| Blank page / 500 error | Check `xampp_error.log`; make sure the folder name has no trailing space |
| Login always fails | Re-run `database/install.php` (resets `admin` / `admin123`) |
| Charts not showing | Charts are loaded from `assets/vendor/chart.umd.min.js` — keep that file |
| Change DB user/password | Edit `config/db.php` **and** `database/install.php` |
